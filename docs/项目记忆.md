## 4. 角色与审批铁律

| 角色 | 端 | 权限 |
|------|----|------|
| VILLAGER | H5 | 资料、匹配政策、申报、看自己的记录 |
| VILLAGE_ADMIN | PC | 仅本村；初审通过/驳回 |
| TOWN_ADMIN | PC | **只能看 `PENDING_TOWN`**（初审通过后）；终审 |
| SYS_ADMIN | PC | 用户/政策/日志；**禁止审批** |

状态机：`DRAFT`（仅村民可见，不进审批列表）→ `PENDING_VILLAGE` → `PENDING_TOWN` → `PENDING_DISBURSE`（待发放，镇终审 PASS 后）→ `DISBURSED`（已发放，镇管发放后记金额），或 `REJECTED`。`APPROVED` 仅作历史数据兼容（statusLabel「已通过」）。  
镇管即使传 `status=PENDING_VILLAGE`，后端也强制只返回待终审；镇管 list 用 `tab` 参数（pending/disbursing/disbursed/rejected），村管用 tab（pending/approved/rejected）。  
**后台三端统一账号 `admin` / 密码 `123456`**：登录接口支持 `{username,password,role}`，按「账号+角色」定位（前端各自固定本端角色）；旧手机号登录仍兼容。

## 5. 政策匹配（MySQL 多条件 WHERE）

- 文档：`docs/04-policy-match-algorithm.md`（v2.0，已替代原 WRS 加权打分）
